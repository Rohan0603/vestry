## The disposition (negative decision)

**P2a — dismissed as a required adapter capability.** The default `opencode run --format json` profile is an owned independent child process with no dependency on a long-lived serve session. A cooperative `POST /session/:sessionID/abort` may be attempted only if a separately qualified `serve` profile is admitted, and its acknowledgement is **never** termination evidence. Vestry verifies that all owned descendants are gone by independent creation-time Win32 Job Object containment/enumeration (or the POSIX group observer), then reconciles leases and uncertain effects. If containment/observation is unavailable or inconclusive: deny/recover-block; no fallback to "abort returned success". The two historical hard-kill-orphan reproductions remain motivation, not a PASS for Vestry's unimplemented Job Object. Runtime proof remains **VES-25/VES-26**.

**P6 — dismissed as a prerequisite for the default CLI profile.** That profile calls no server HTTP endpoint. Live-probing `/event`, `/global/*`, auth writes or session abort on the Owner's OpenCode installation gives no acceptance benefit for the profile and may change external state. If a server-backed capability is ever actually required, a separately version-pinned, loopback-authenticated, isolated test server must qualify the exact needed routes, port discovery, auth, SSE and failure cases before admission; no silent fallback to serve. Forbidden global mutation routes stay forbidden.
